01  Overview
knurls.me is a production-deployed URL shortening platform engineered for real workloads — not a tutorial project. It combines a Spring Boot backend with Redis-backed caching and rate limiting, PostgreSQL for durable persistence, JWT + OAuth2 authentication, and click analytics built in from day one.

Every design decision was made with production constraints in mind: Redis-cached redirects for sub-millisecond lookups, IP-based rate limiting to prevent abuse, token rotation for session security, and indexed database queries for analytics at scale.

02  Features
⚡
Instant Short URLs
Base62 encoding generates collision-resistant short codes. Redis caches the lookup so redirects resolve in sub-millisecond time without hitting the database.
🔗
Custom Aliases
Authenticated users can define their own short alias per link. Alias uniqueness is enforced at the database level with a dedicated index.
⏱
Link Expiration
Configurable TTL per link. Expired URLs return gracefully — no broken redirects. Expiry is enforced at both the application and cache layer.
📊
Click Analytics
Per-link click tracking with timestamps, browser, device type (mobile/desktop/tablet), referrer, and IP-based geolocation metadata — paginated for large datasets.
🔐
JWT + OAuth2 Auth
Access + refresh token flow with rotation on every use. Google OAuth2 login alongside email/password. BCrypt password hashing. Zero server-side sessions.
🛡
Redis Rate Limiting
50 requests/minute per IP enforced via Redis atomic increments with a sliding expiration window. Abuse is blocked before it reaches the application layer.
🗂
URL Dashboard
User-scoped management dashboard: view, search, and delete your links. Sorted and paginated for performance even with large link sets.
👤
Role-Based Access
USER and ADMIN roles enforced via Spring Security. Admin endpoints are not exposed in public documentation — secured and hidden from standard API consumers.

06  Engineering Highlights
01
Redis Caching & Rate Limiting
Two distinct Redis use cases in one project. Short URL lookups are cached so the database is bypassed entirely on hot paths — redirects resolve near-instantly. A separate Redis key per IP implements atomic increment-based rate limiting with a sliding window, blocking abuse before it reaches the application layer.
Redis 7Read-through cacheAtomic incrementsRate limiting
02
Stateless JWT + OAuth2 Security
Dual-token flow: short-lived access tokens for API requests, longer-lived refresh tokens rotated on every use. Google OAuth2 integration allows social login alongside traditional email/password. Spring Security filter chain validates every request; no server-side session state means the system is horizontally scalable from day one.
Spring SecurityJWTOAuth2Token rotation
03
Analytics Engine Design
Every redirect captures click metadata: timestamp, browser, device category, referrer URL, and IP-derived geolocation. Analytics are stored in a separate indexed table keyed on URL ID, keeping the hot redirect path clean while enabling efficient aggregation queries. Pagination prevents unbounded result sets on high-traffic links.
PostgreSQLIndexed queriesPaginationClick capture
04
Database Index Strategy
Five targeted indexes across two tables cover every hot-path query: short_code and custom_alias for redirect lookups, user_id for dashboard listing, created_at for sorted pagination, and url_id on the analytics table for click aggregation. No full-table scans on any production path.
